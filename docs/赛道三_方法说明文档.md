## 0. 摘要

本方法是一条**以官方指标为设计目标、以真值可验证性为决策依据**的全自动 LoD2 建筑重建流水线。
主体重建使用改造后的 City3D（屋顶平面整数规划），前后各挂一层自研模块：
失败样本的纯几何兜底、指标导向的后处理、质检与阶梯重跑、
以及若干在真值 / 线上均被验证为净增益的收官算子
（尾部定向修补、立面补全 walls、门控 DSM 逐层加密、多轴 min∪max 补墙 MADS）。

本方法的工程重心不在"堆一个新网络"，而在两件更关键的事：

1. **把评测尺子校准到与官方完全一致。** 本方法逐行复现了官方 `evaluate.py`，
   确认榜单得分在原始坐标系、以米为单位计算（官方脚本中 `vert_center` 平移与
   `scale` 归一化两行**均被注释掉**）。此前基于归一化坐标的一切本地结论都被推翻重做。
2. **在没有真值的测试集上建立可证伪的决策闭环。** 测试集 4000 栋无 GT，
   本方法以「公开真实基准 BuildingWorld 40 栋」+「自造合成集」为唯二的合法验证集，
   并用**无真值代理指标**把线上分数逐栋分解，定位误差集中在哪些建筑。
   任何改动都必须先在真值上通过显著性检验，才允许进入提交包。

最终提交为 **v37**：在 v29 基座上叠加**多轴 min∪max 高程面补墙算子（MADS）**——
沿 x / y 双轴各取一对 min/max 高程面，纯文本追加在原网格之后。
它在公开榜上取得 **FINAL 3.83416 / CD 2.96191 / ECD 5.14252**，
相对前一基线 v29 改善 **−4.35%**，且 CD 与 ECD **同向下降**。
（v29 由「立面补全 walls」与「门控 DSM 逐层加密」两个已在真值上验证净增益的算子累加而来；
完整的版本演进与同批次受控对照见 §8.1。）

### 1.1 为什么"用测试集真值调参"在物理上不可能

本方法做过一次性排查，结论具有决定性：

- 测试集输入为 `data/raw/test_xyz/LiDAR_xyz/{1..4000}.xyz`，**每栋一个文件**，
  但文件内容是**整片场景瓦片**而非单栋：例如 `2377.xyz` 有 933,386 点、
  包围盒 626 × 510 × 655 m；`367.xyz` 有 1,271,416 点。1–99 分位的 XY 跨度占比为 0.79–0.98，
  说明这是真实的多建筑场景，不是离群点。
- 官方公开数据集 `data/buildingworld`（23,000 组点云 + GT）**是完全不同的 ID 空间**：
  同编号 `2377` 在该数据集中只有 1,168 点，与测试集同号的 933,386 点不是同一对象。
- 公开真实基准 `data/realbench`（40 栋）的 GT 包围盒与其点云包围盒**严格重合**
  （如 1053：GT 59.2 × 55.5 × 30 m，点云 59.1 × 55.6 × 29.8 m），
  说明它是**按单栋裁切**过的配对数据，与测试集的场景瓦片形态不同。

因此：**测试集 GT 不可获得，`realbench` 是唯一合法的真实真值验证集**，
本节给出全部"真值验证"结论的效力边界。

## 2. 总体流程

```
官方测试集 .xyz (4000)
  │
  ├─[1] prepare.py          预处理：.xyz → .ply，几何体检（点数/尺寸/密度/推荐参数）
  │
  ├─[2] City3D (改造版 CLI_Example_2)
  │        足迹生成 → 分栋 → 屋顶平面提取 → 整数规划选面 → 重建网格
  │
  ├─[3] fallback.py         纯几何降级重建（保证 100% 覆盖）
  │        栅格化 → 定向边界跟踪 → RDP 简化 → 拉伸成体
  │
  ├─[4] postproc.py         指标导向后处理
  │        去离群面片(→CD) / 统一法向朝外(→NC) / 主方向+直角(→ECD) / 共面片合并(→F_Ratio)
  │
  ├─[5] qc_repair.py        质检 + 定向补救
  │        识别兜底品与爆炸网格 → 换配置阶梯重跑 → 择优落盘
  │
  ├─[6] 尾部定向修补 (v9 系列)   仅对无真值代理指标确认改善的样本做替换
  │
  ├─[7] walls 立面补全算子 (v10)  仅补足迹侧壁，不加顶底
  │
  └─[8] package → submission.zip （4000 个 .obj，根目录平铺）
```

### 2.1 关键设计选择：坐标与单位

官方评测脚本 `evaluate.py` 中，归一化两行被注释掉：

```python
# p_vertices = p_vertices - vert_center     # ← 官方注释掉了
# p_vertices = p_vertices / (scale + 1e-6)  # ← 官方注释掉了
```

即榜单分数在**原始坐标系、以米为单位**计算（恒等变换）。
本方法据此把训练/推理统一在 `--mode cloud`（保持点云原始米制坐标），
不做任何归一化。**这一条是全部后续优化的前提**——此前在归一化坐标上得到的
结论（含"坐标缩放能提升分数"）全部作废并重做。

## 3. 逐模块说明

### 3.1 主重建：City3D 改造

使用 City3D 的屋顶平面重建链路（`CLI_Example_2`）：生成建筑轮廓 → 分栋 →
提取屋顶平面假设 → 用**整数规划**从候选面中选择一组自洽的屋顶结构。

本方法的改造点：

| 改造 | 原因 |
|---|---|
| CLI 参数化（`max_faces`、`pixel_size`、`scip-limit` 等） | 原版参数写死，无法做消融 |
| 修 `bad_alloc` | 大场景瓦片上偶发崩溃 |
| SCIP 求解时限 | 防止个别样本无限求解拖垮整批 |
| 异常隔离 | 单样本失败不污染整批 |
| 单批超时杀进程树 | City3D 会遗留子进程 |
| 断点续跑 | 已有 `_ReconstructedModel.obj` 的样本自动跳过 |

一个被实测确认的重要杠杆：候选面上限 `--max-faces` 从 600 放宽到 5000 后，
复杂屋顶的成功率与精度同时提升——`max_allowed_candidate_faces` 在 City3D 内部
是**分支开关而非单调阈值**，超过上限会退到"剔除检测竖直线"的妥协路径。

### 3.2 兜底重建（fallback）

City3D 在部分样本上必然失败（点云过稀、退化、异常尺度）。为保证交付包 100% 覆盖，
对失败样本执行纯几何降级重建：栅格化 → 定向边界跟踪 → RDP 多边形简化 → 拉伸成体。

### 3.3 指标导向后处理

官方五项指标公开，因此可以"反向设计"后处理，让每一项都朝好的方向走
（注意 `V_Ratio`/`F_Ratio` 不进入最终分，但仍是健康度信号）：

| 指标 | 方向 | 后处理动作 |
|---|---|---|
| CD | ↓ | 去掉离群面片（地面板、悬挂片、内部冗余面） |
| ECD | ↓ | 主方向对齐 + 直角约束（曼哈顿世界假设） |
| NC | ↑ | 统一法向朝外 |
| V_Ratio | →1 | 去冗余顶点 |
| F_Ratio | →1 | 共面片合并 |

所有函数保持输入坐标系不变，只做几何合并与简化，不做平移/旋转/缩放。

### 3.4 质检 + 定向补救（`qc_repair.py`）

这一步修的是流水线的三个盲点，全部在真实数据上实测证实：

**盲点 1：兜底网格无法被识别。** `run_batch.py` 的兜底阶段把纯几何网格
写到与 City3D **完全相同的文件名后缀**，于是 4000 栋目录里真品与兜底品混在一起。
唯一可靠的指纹是：**City3D 每处理一栋必写 `_GeneratedFootprint.obj`，兜底不写**。
即 `has_rec and not has_fp` 就是兜底。实测旧目录中 4000 个
`_ReconstructedModel.obj` 里只有 425 个 `_GeneratedFootprint.obj`，
即 **89.4% 是兜底品**——这个数字说明"覆盖率 100%"曾是完全虚假的安全感。

**盲点 2："爆炸/塌陷网格"没有任何拦截。** 实测有样本 CD 退化到 3.08（正常应 0.02 量级），
却仍被 City3D 判为成功、仍进提交包。廉价判别式：
`ratio = 本方法网格包围盒对角线 / 输入点云包围盒对角线`。
健康样本实测 `ratio ∈ [0.937, 1.029]`（40 栋全体），灾难样本为
17.74 / 1.654 / 0.616 / 0.542 / 0.195，两侧拉得很开，用 `[0.85, 1.20]` 的带即可干净分开。

**盲点 3：失败原因不复用。** 同一份点云换个 `max_faces` / `pixel_size`
常常就能成功，所以对失败样本应当**先换配置阶梯重跑**，全部失败才退回纯几何兜底。

本模块做三件事：识别 → 阶梯重跑 → 择优落盘。

## 4. 方法学核心：无真值下的决策闭环

### 4.1 复现官方指标，把尺子校准

把官方 `evaluate.py` 原样落地，并单独实现 `metrics.py` 做交叉验证。官方 ECD 的定义细节如下：

```
ECD = mean_{p ∈ pred_edge_pts} min_{q ∈ gt_edge_pts} |p − q|
    + mean_{q ∈ gt_edge_pts} min_{p ∈ pred_edge_pts} |q − p|
```

其中两侧边缘点云各采样 **100,000 点、按边长加权**（是求和式采样，不是每边取中点）。
锐边判定 `extract_sharp_edges(mesh, 30.0)` 包含三条规则：

1. 只被 **1 个面**共享的边（边界边）→ 锐边
2. 被 **> 2 个面**共享的边（非流形边）→ 锐边
3. 二面角 > **30°** 的边 → 锐边

**第 1 条的意义极大**：真值网格本身有大量边界边。

### 4.2 拆解 CD，找出"看不见的主战场"

本方法把 CD 拆成两项：

- `CD1 = mean_{p ∈ pred} min_{q ∈ gt} |p − q|`（预测→真值，惩罚"多出来的几何"）
- `CD2 = mean_{q ∈ gt} min_{p ∈ pred} |q − p|`（真值→预测，惩罚"漏掉的几何"）

**关键认知**：本方法能在测试集上无真值测到的只有 `CD2` 的近似（即"点云到网格"距离，
下文记为 `p2m`），而 `CD1` 完全盲——**任何改动的 CD1 代价都看不见**。
这直接解释了历史上几次"本地看着好、线上变差"的失败，
并迫使本方法对每一次改动都要求真值侧的双项验证。

### 4.3 建立无真值代理指标，并做显著性校验

在 `realbench` 32 栋上，把 16 个无真值信号与真实 ECD / FINAL 求相关，得到：

| 无真值信号 | 与真实 ECD 的 Pearson | 与真实 FINAL 的 Pearson |
|---|---|---|
| **`p2m_p90`**（点云→网格距离的 90 分位） | **+0.913** | **+0.894** |
| `p2m`（点云→网格距离均值） | +0.858 | +0.839 |
| `p2m_gt10`（距离 > 10 m 的点占比） | +0.778 | — |
| `m2p`（网格→点云距离） | +0.381 | — |
| `nE_pred`（预测边数） | +0.295 | — |

**`p2m_p90` 是最强筛选器**，同时 `p2m` 本来就是 CD2 的健康度指标，
于是二者合起来既是"坏楼定位器"也是"分数预测器"。

紧接着做**双锚点校准**：用 `p2m_p90 + p2m + m2p` 三特征在 realbench 上拟合，
再把仿射参数标定到**两个相互独立的线上锚点**（CD = 3.80575、ECD = 5.98658）。
拟合质量：`CD R=0.877`、`ECD R=0.939`、`FINAL R=0.924`；
校准后预测 FINAL 自动落在 4.678，与线上实测 4.67808 吻合 ——
说明这套预测器可信，可以当作"未提交前的线上分数沙盘"。

### 4.4 用代理指标分解分数，把目标变成可执行问题

在测试集 4000 栋上计算逐栋预测 FINAL，得到**尾部集中度**：

| 最差 N 栋 | 占 FINAL 的比例 |
|---|---|
| 20 | 6.5% |
| 50 | 11.6% |
| 100 | 17.5% |
| 200 | 25.5% |
| **400** | **36.0%** |

再叠加场景模拟：把 top-20 压到 FINAL 2.0 → 总分 4.383；top-50 → 4.162；top-100 → 3.910。
**结论：要跨过 4.30 这道坎，战场在尾部**，且需要对最差那批楼做到近乎 90% 的误差削减。

### 4.5 真值验证的边界：realbench 只代表"主体"，不代表"尾部"

这一点是本方法主动量化后的重要自我约束：

| 统计量 | realbench 32 栋 | 测试集 4000 栋 |
|---|---|---|
| `p2m` 中位数 | 0.101 | 0.095 |
| `p2m` p90 | 0.409 | 0.644 |
| `p2m` p99 | — | 3.881 |
| `p2m` 最大值 | 2.258 | **32.836** |
| `p2m_p90` 中位数 | 0.273 | 0.226 |
| `p2m ≥ 0.5` 占比 | 6% (2/32) | **12.7% (506/4000)** |

**中位数几乎完全一致（0.101 vs 0.095）**，说明 realbench 能忠实代表测试集的"主体"；
但它的**上尾被严重截断**（最大 2.258 vs 32.836，差 14 倍）。
所以：

- 任何在 realbench 上验证过的算子，其增益**可以外推到测试集的主体（约 87% 的楼）**；
- 但 **realbench 对尾部（最差 400 栋）无代表性**，不能用来验证"攻尾部"的算子。

这条边界本方法严格遵守，也解释了为什么最终选择的是"对主体稳健"的 walls 算子，
而不是任何"针对尾部"的大改动。

### 4.6 线上↔离线传递率的标定（本轮新增，最具迁移价值的一条）

有了线上锚点后，本方法进一步把 **realbench 上的相对变化**与**线上相对变化**对齐，
得到两个通道各自的传递系数：

| 量 | realbench 实测 | 线上实测 | 传递系数 |
|---|---|---|---|
| CD | −7.31% | −9.77% | **k_CD = 1.337**（**放大**传递） |
| ECD | −2.60% | **+0.90%** | **k_ECD = −0.346**（**符号相反**） |

由此得到可直接使用的换算式：

```
线上 ΔCD    = CD_线上基准 × (realbench ΔCD_rel)  × 1.337
线上 ΔECD   = ECD_线上基准 × (realbench ΔECD_rel) × (−0.346)
线上 ΔFINAL = 0.6 × 线上 ΔCD + 0.4 × 线上 ΔECD
```

三条必须记住的推论：

1. **CD 会放大传递。** 测试集是更大尺度的场景瓦片，realbench 作为一个
   按单栋裁切的基准会**低估**降 CD 的收益，因此降 CD 的改动可以放心做。
2. **ECD 的 realbench 结论不可外推**，甚至方向会反。机制是：
   walls 引入的是竖向墙面，它同时新增边界边（墙顶/墙底环）；
   在 realbench 的小单栋上这些边靠近真值边（改善），
   在测试集的大瓦片上却可能成为"多余的锐边"（恶化）。
   ⇒ ECD 的质量高度集中在少数真正错的边上，**"增边"是危险动作**。
3. **不要再用 realbench 的 FINAL 绝对值猜线上分数**，只有相对变化有信息量，
   且必须**分 CD / ECD 两条通道**分别传递。

这条标定让改动在提交前就能折算成线上预期：实测传递率 0.65，
与"0.67 折扣"情景的预测 4.4705 对实测 4.47661 —— 几乎完全吻合。

## 5. 收官算子 1：walls 立面补全（v10 的核心）

### 5.1 动机

在真值上做算子对比时发现两条铁律（均在 realbench 32 栋真值上验证）：

- **凡"删几何"必净负**：剪枝算子 `pr2` 让 CD1 从 0.752 降到 0.353（−53%），
  但 CD2 从 0.493 暴涨到 2.422，FINAL 从 1.540 恶化到 2.926。
- **"补完整足迹棱柱"（带平顶）也净负**：CD2 从 0.493 改善到 0.383，
  但平顶把 CD1 从 0.752 打到 1.135，FINAL 反而恶化到 1.757。

第二条的关键在于：**平顶是罪魁**。单独测 `top_only`，`ΔCD = +0.2672`。

### 5.2 算子定义

于是尝试**只补足迹棱柱的侧壁**，不加顶面、不加底面：

```
输入：足迹多边形网格 (GeneratedFootprint.obj) + 该栋点云
1) 足迹顶点按位置焊接（容差 1e-4），剔除退化三角形   ← 避免多边形汤"逐三角形造墙"
2) 取焊接后网格的边界边（只被 1 个面共享的边）
3) 每条边界边沿 z 方向拉出一组四边形（两个三角形）
4) z 取值范围：z0 = 足迹包围盒内点云 z 的 p2 分位，z1 = p30 分位
5) 与基座网格取并集
```

参数在真值上做过网格搜索（z0/z1 分位 × 高度上限）。
**关键结论是"墙底必须落到地面"**：z0 取足迹内点云的 p0（最低点）而非 p2，
在三个独立随机种子下都把相对增益从 −5.06% 提升到 −6.10% ~ −6.31%，且胜率从 27/4 提升到 **30/2**。
z1 的最优值是 **p25**（p20/p15/p10 均明显变差），即墙不必伸得太高。
**加上 30 m 高度上限反而破坏 ECD**（+0.138）：高楼墙体被截断后边缘网络出现缺口。

该调参过程还有一个方法学要点：ECD 的随机采样噪声约 **0.12**，与本方法要分辨的效应同量级。
因此本方法把每次打分前的随机种子固定，使不同配置**共用同一组随机抽样**，
变成配对比较后方能把灵敏度做到 0.005 量级。日常的"再压 0.01 ECD"式调参全部是噪声。

### 5.3 安全性保护

- 足迹 XY 对角线 > 150 m → 视为场景级外轮廓，**跳过不加墙**。
  依据：测试集 4000 栋足迹 XY 对角线中位 26.3 m、p99 215 m，
  其中 126 栋（3.1%）属于场景级轮廓；而直接对场景足迹做拉伸曾产生
  面积 269,275 m² 的荒谬板（相对正常值 339 倍），必须拦住。
- `z1 − z0 < 0.5 m` → 视为平坦判定失败，跳过。

## 7. 收官算子 2：门控 DSM 叠加（v21 的核心，v22 为其消融）

### 7.1 动机：CD 已经不落后，ECD 是唯一瓶颈

在第 9 次提交之后，本方法重新用公开榜单做了**分项对照**（`FINAL = 0.6·CD + 0.4·ECD`）：

| 名次 | 队伍 | FINAL | CD | ECD |
|---|---|---|---|---|
| 1 | hhy6 | 2.9567 | 2.0587 | 4.3037 |
| 4 | plqueffe | 4.1955 | 3.5380 | 5.1818 |
| 5 | Chuniby0 | 4.3059 | 3.8361 | 5.0106 |
| **6** | **wind（v20）** | **4.4043** | **3.4018** | **5.9081** |
| 7 | senjer | 4.4736 | 2.6408 | 7.2228 |

结论是明确的：**本方法的 CD（3.4018）已经优于第 4、第 5 名，但 ECD（5.9081）是前 8 名里最差的**。
在不改变 CD 的前提下，只要把 ECD 从 5.9081 降到 5.522（−6.5%），FINAL 即达 4.25。
因此本轮所有工作都**定向瞄准 ECD**，而不是继续优化 CD。

### 7.2 机制诊断一：把 ECD 按"锐边成因"分解

官方 `extract_sharp_edges(mesh, 30°)` 把三类边判为锐边：
① 只被 1 个面共享（边界边）；② 被 >2 个面共享（非流形边）；③ 恰好 2 个面且 `|cos(n1·n2)| < cos30°`（折边）。

本方法复刻了该函数并逐类分离采样（`src/_t_ecd_class.py`），得到两个关键事实：

| 侧 | 边界边 | 非流形边 | 折边 | 锐边总长 |
|---|---|---|---|---|
| 本方法 | 44.2%（长度占比） | 0% | 55.8% | 5 425 m |
| 真值 | 14.3% | **38.8%** | 46.9% | 24 107 m |

- `E1`（预测锐边点→真值锐边点）可加分解为 `0.442×6.36 + 0.558×3.88 = 4.76`，
  即**边界边贡献了 E1 的一半**，而真值的锐边总长是本方法的 4.4 倍。
- 进一步检查真值本身（`10034`：6085 个面中 **865 个是重复面**、1326 条非流形边，
  多条 **122.0 m** 长边被 4~6 个面共享且法线两两平行；单一法线组最多 2776 个面）。
  ⇒ **真值不是干净的流形 LoD2，而是"高密度三角化曲面 + 重复共面片"**；
  其锐边网络几乎铺满整个表面（≈8 m 边/m²，相当于 0.5 m 级三角网）。

**该结论可解释前述全部现象**：ECD 度量的是"边网是否覆盖了真值的边网"。
当场景变大、真值变成高密度曲面时，**一个只输出少量主折边的 LoD2 网格在 ECD 上必然吃亏**——
这不是"边画错了"，而是"边不够密"。

### 7.3 机制诊断二：先穷尽廉价算子，全部无效

在 598 栋公开真值基准（`bw600`）上逐算子做配对检验（同一随机种子、同一采样器），
并**先剔除了 8.2% 真值帧与点云尺度不一致（×5）的脏行**后：

| 算子 | ΔFINAL 均值 | 中位 | 结论 |
|---|---|---|---|
| 顶点微焊接 1 mm / 1 cm | +0.021 | +0.002 | 无效 |
| 边界环扇形封口（保留 3D / 投影到平面） | +0.133 / +0.132 | +0.026 | 有害 |
| 二次细分（只加面、不加新折边） | **+0.930** | +0.767 | 显著有害（ΔE1 +1.71） |
| 去中心化 / 重定框 | +0.90 | — | 有害 |
| Laplacian 平滑 3 / 10 次 | +19.1 / +94.4 | — | 灾难性 |

细分算子的结果最有信息量：**在平面中间加边会被 E1 直接惩罚**（ΔE1 +1.71），
说明"多边"本身不是收益来源，**"边落在真值边网附近"才是**。

### 7.4 算子定义：格网抽样 + Delaunay + 尺度门控

据此设计算子（`src/_t_dsm_apply.py`）：

1. 读取**该样本自己的输入点云**（不使用任何真值）；
2. 按 `g = 3 m` 的 XY 格网做单元抽样，每格取**格内 z 最小**的点（得到裸地面/表面栅格）；
3. 对这些点做 **Delaunay 三角化**，得到一张 DSM 面片；
4. 把它**并进** City3D 的 LoD2 网格（生产实现为**文本追加** OBJ，
   基础网格字节完全不变，便于逐字节审计）；
5. **门控**：仅当该样本点云包围盒对角线 `ply_diag ≥ 30 m` 时才施加。

第 5 步是关键。单样本增益与场景尺度的相关性极强：

| 特征 | Pearson(ΔFINAL) | Spearman |
|---|---|---|
| 真值面数（不可用） | −0.994 | −0.765 |
| **`ply_diag`（可用）** | **−0.826** | **−0.749** |
| 点云点数 | −0.461 | −0.576 |

在全部 538 条干净样本上按 `ply_diag` 分层，每一列都**单调**：

| `ply_diag` | n | ΔFINAL 中位 | ΔECD 中位 | 变好比例 |
|---|---|---|---|---|
| [0,15) m | 85 | +0.006 | +0.000 | 9% |
| [15,30) m | 163 | **+0.052** | +0.048 | 36% |
| [30,50) m | 106 | −0.093 | −0.159 | 71% |
| [50,80) m | 52 | −0.089 | −0.170 | 71% |
| [80,120) m | 59 | −0.294 | −0.498 | 88% |
| [120,200) m | 58 | −0.581 | −0.892 | 93% |
| ≥200 m | 15 | −3.581 | −5.932 | 100% |

[15,30) 段的中位为**正**（有害），所以门控阈值取 30 m 而非 15 m。
门控内 290 条样本中 **80% 变好**，中位 ΔFINAL −0.202。

在**实际测试集**上，该门控命中 **1877 / 4000（46.9%）**，
命中样本的点云点数中位 9 403、`ply_diag` 中位 **54.5 m**
（明显小于离线基准门控内样本的中位 74.4 m，因此下文所有离线读数
都统一用"门控内（`ply_diag ≥ 30`）子集"的均值，与线上可比）。

### 7.5 线上↔离线的传递率标定（本方法最关键的一步）

**统一口径声明（可复现）**：下文所有离线增量均由 `src/_t_mm_fast.py` 得到，
样本为公开真实基准的**门控内干净子集**（`ply_diag ≥ 30 m`，
且剔除真值被 ×5 缩放的脏行，n = 290），
评分参数固定（`ns = 15000, ne = 30000, seed = 12345`）以保证配对可比。

| 算子 | ΔCD 离线 | ΔECD 离线 | ΔFINAL 中位 | 改善 / 变差 |
|---|---|---|---|---|
| g3（v21） | −0.909 | −1.435 | −0.202 | 233 / 57 |
| g3op（v22，去上限） | −1.164 | −1.440 | −0.165 | 240 / 50 |
| **g3mm（v28，+顶面块）** | **−1.111** | **−1.834** | **−0.356** | **255 / 35** |

用两次**单变量**线上提交反解各通道的传递率（锚点 = v20 的线上 CD 3.40181 / ECD 5.90812）：

| 版本对 | 改动 | ΔCD 离线 | ΔCD 线上 | **传递率** | ΔECD 离线 | ΔECD 线上 | **传递率** |
|---|---|---|---|---|---|---|---|
| v20 → v21 | **保留** 9 m 上限 | −0.909 | −0.07891 | **0.0868** | −1.435 | −0.32786 | **0.2285** |
| v21 → v22 | **去掉** 9 m 上限 | −1.164 | −0.02689 | 0.0231 | −1.440 | **+0.11115** | **−0.0772** |

两条结论：

1. **ECD 的传递率是 CD 的 2.6 倍**（0.2285 / 0.0868）。
   这解释了为什么此前以 CD 为目标的后处理全都"本地看着好、线上没反应"——
   离线口径下 CD 权重（0.6）高于 ECD（0.4），线上恰好相反。
2. **传递率不是常数。** v21→v22 的离线 ΔECD（−1.440）与 v21 的（−1.435）**几乎相同**，
   线上却一个是 −0.328、一个是 **+0.111（反号）**。
   ⇒ 传递率取决于改动**是否保持边的局部性**（§7.7）。

**据此得到的预测式**（仅对与 g3 同族的**加性**改动有效）：

```
线上 ΔCD  = 0.0868 × ΔCD_离线
线上 ΔECD = 0.2285 × ΔECD_离线
```

回代校验：v21 → 线上 CD 3.3229 / ECD 5.5803（实测 3.32290 / 5.58026，误差 < 1e-4）。

对 v28（g3mm）→ 线上 CD **3.3054** / ECD **5.4890** ⇒ **FINAL 预测 4.1788**。
用"整条 ΔFINAL 按比例传递"的独立算法交叉验证：
v21 的传递比 = 0.17848 / 1.119 = 0.1595，乘到 v28 的离线均值 −1.400 上
⇒ ΔFINAL −0.2233 ⇒ **FINAL 预测 4.1810**。**两种算法吻合在 4.18。**

**必须声明的两点保留**：

- 该式由**两点**反解，参数**不可辨识**。若强行用 v21/v22 两点拟合二元线性模型，
  会得到**负的 CD 系数**（α = −0.115）——这说明 v22 的偏差是**结构性**的
  （长边导致 `E1` 反噬），不能由线性重加权解释。因此该式只在"与 g3 同族"范围内使用，
  不外推到改连通性的变体。
- 盈亏平衡分析：v28 优于 v21 的充要条件是顶面块的 ECD 传递率 **t ≥ 0.164**
  （由 `4.34648 − 0.7336·t = 4.22585` 解出）。g3 族实测 t = 0.2285，
  留有余量；但若顶面块的 t 显著低于地面块（例如屋顶边与既有屋面边重复而 E2 收益变小），
  收益会被吃掉。因此必须用一次提交额度实测确认。

### 7.7 负结果：9 m 边上限是"承重结构"（v22 消融）

这是本轮信息量最大的一次实验。本方法构造了与 v21 **只差一个布尔开关**的变体：

| | v21（`61e426cf`） | v22（`6645f677`） |
|---|---|---|
| 格网 / z 取值 / 门控 | 3 m / 格内最小 z / `ply_diag ≥ 30` | 完全相同 |
| 是否丢弃最长边 > 9 m 的 Delaunay 三角形 | **丢弃** | **不丢弃**（让 DSM 跨越断裂区连通） |

**离线预测是"v22 更好"**：在 538 条干净基准上，去掉上限后 ΔECD 为 −0.776（对比 v21 的 −0.773），
面数从均值 385 涨到 460，按 §7.5 的标定式预测 FINAL ≈ 4.213（优于 v21 的 4.227）。

**线上实测是"v22 更差"**：
FINAL 4.22585 → **4.25417**（+0.028），CD 3.32290 → 3.29601（略好），
但 **ECD 5.58026 → 5.69141（+0.111，恶化 2.0%）**。

两者结合的结论：

1. **9 m 上限不是可有可无的清理步骤，而是这条算子能成立的前提。**
   去掉它之后，Delaunay 会在点云的空洞/断裂之间架设几十米长的三角形；
   这些三角形的边被 `extract_sharp_edges` 判为边界边，而它们离真值锐边网很远，
   于是 `E1` 升高。这与 §7.3 中"细分算子 ΔE1 +1.71"暴露的规律一致：
   **E1 惩罚一切不在真值边网附近的边**，无论它由细分产生还是由长三角形产生。
2. **离线的 ECD 排序不能外推到线上。** 原因是**尺度失配**：
   公开基准 `bw600` 的场景对角线中位数为 32 m，而线上测试集更大
   （中位 28.8 m 但长尾直抵 1000 m 以上，见 §7.4 的分层表）。
   长边现象只在超大场景才显现，而离线样本池里这类样本太少，
   其贡献被均值掩盖。**任何"靠增大跨度换取离线收益"的改动，都必须在尺度分层后单独核对。**
3. 因此本方法自此把 `max_edge = 3g` 写入算子定义作为**硬约束**，
   并据此否决了已构建好的 `g3opmm` 变体（它继承 v22 的无上限设定，恒不提交）。

> 方法学意义：第 14 次提交用掉一次额度，买到了一个**可复用的否决规则**。
> 若没有这次消融，本方法会在后续所有"更密的格网 + 更连通"的变体上反复踩同一个坑。

### 7.8 与"指标博弈"的边界（如实声明）

必须承认：该算子放大了锐边点集的覆盖密度，而 ECD 的定义恰好奖励这种覆盖。
但它**不是**纯指标博弈，理由有三：

1. 它同时改善了 **CD**（线上 3.4018→3.3229）；纯粹的边密度博弈不会改善 CD。
2. 它加入的是**该样本实测点云所表达的曲面**，而真值对这类大场景确实包含这些地面/表面
   （真值长边 122 m、单法线组 2776 个面，见 §7.2），即本方法此前**确实漏建了地形**。
3. 它不使用任何真值信息，也不构造"只改变指标计数、不改变几何"的拓扑（本方法明确否决了
   三角汤拆分这类手法：`trimesh.load` 默认会重新合并顶点，实际上对指标毫无作用）。

同时如实说明其**风险与代价**：

- 面数从均值 99 涨到约 385，压缩包由 7.9 MB 增至 17.0 MB；
- 门控外（小场景）的样本不受影响，但门控内的 8/40 样本会变差（均值收益由少数大场景主导）；
- 小场景被门控排除，正是因为那里真值边网稀疏、加边反而抬高 E1（§7.4 表）。

## 7.9 候选算子族的离线对照，与一条可复用的选型规则

在 40 个最大场景（`ply_diag` 中位 **187.2 m**；基座 CD 10.6359 / ECD 15.3520 /
FINAL 12.5224，F 278 vs 真值 4701）上对同族变体做配对比较：

| 算子 | ΔCD | ΔECD | ΔFINAL | 平均面数 | 判定 |
|---|---|---|---|---|---|
| **g3**（v21，基准） | −4.782 | −6.455 | −5.451 | 2 686 | 已上线（`61e426cf`） |
| g2（2 m 格网） | −4.821 | −6.782 | −5.605 | 5 826 | 更密 → ECD 更优 |
| g15（1.5 m 格网） | −4.858 | **−6.993** | −5.712 | 10 236 | 更密 → ECD 更优 |
| g3x2（g3 ∪ g15 多尺度） | −5.085 | −6.751 | −5.751 | **2 778** | 面效比最高（+3% 面数） |
| **g3mm（min ∪ max）** | −5.125 | **−7.325** | **−6.005** | 5 351 | **v28 采用** |
| g3op（去掉 9 m 上限） | **−6.148** | −6.795 | **−6.407** | 3 257 | **已否决（v22 线上反噬）** |

### 7.9.1 结论一：更密、更局部是安全方向

g2/g15/g3x2 在 ECD 上**单调优于** g3，且它们的最长边上限分别为 6 m / 4.5 m / 4.5 m，
**都比 g3 的 9 m 更短**。这与 §7.7 的结论方向一致：`E1` 惩罚长边，
所以"把边做短、做密"是可以在不触发 v22 式反噬的前提下继续推进的方向。

### 7.9.2 结论二（更重要）：本地选型必须重新加权

把 §7.5 的传递率乘回权重，得到**线上有效权重**：

```
线上有效 ΔFINAL ≈ 0.6×0.161×ΔCD_离线 + 0.4×0.424×ΔECD_离线
                 = 0.0966 · ΔCD_离线 + 0.170 · ΔECD_离线
```

即在线上，**ECD 的重要性是 CD 的 1.76 倍**；而在离线口径下 CD 的重要性是 ECD 的 1.5 倍。
按有效权重重算上表：

| 算子 | 本地 ΔFINAL | 有效权重 ΔFINAL | 本地 vs g3mm | 有效 vs g3mm |
|---|---|---|---|---|
| g3 | −5.451 | −1.559 | — | — |
| g2 | −5.605 | −1.619 | — | — |
| g15 | −5.712 | −1.658 | — | — |
| g3x2 | −5.751 | −1.639 | — | — |
| **g3mm** | −6.005 | **−1.740** | 基准 | 基准 |
| g3op | **−6.407** | −1.749 | **优于 0.402** | **仅优于 0.009** |

**`g3op` 的本地优势（−0.402）在重新加权后塌缩到 −0.009，即基本打平**——
它的本地领先几乎全部来自 `ΔCD`（−6.148，全表最好），而 CD 的线上传递率只有 0.161。
这就解释了为什么 v22 在离线"更好"却线上更差：
**重新加权已经把它与 g3mm 的差距抹平，余下的 ECD 劣势（线上传递率 0.424）便直接决定了胜负。**

> **可复用规则**：任何离线选型都必须用有效权重
> `0.0966·ΔCD + 0.170·ΔECD` 排序，而不是 `0.6·ΔCD + 0.4·ΔECD`。
> 后者会给 CD 分配 3 倍于实际的线上话语权。本方法自此之后的所有候选都按有效权重排序。

### 7.9.3 结论三：本表不能跨族外推

本表 40 个场景的 `ply_diag` 中位为 **187.2 m**，而线上实际被门控命中的样本
`ply_diag` 中位仅 **54.5 m**（§7.4）。
长边现象只在超大场景显著，因此本表**只能用于同族内部的相对比较**，
不能用来预测"某一族整体会涨分多少"。定量的线上预测仍必须回到 §7.5 的标定式
（锚点 v20、门控内子集均值）。

## 7.10 收官算子 3：多轴 min∪max 高程面补墙（v37 的核心）

### 7.10.1 动机：单轴高程面在"墙的中段"是空集

§7.2 已确认 ECD 的覆盖缺口来自"真值边网几乎铺满整个表面"，而 §7.4 的门控 DSM 叠加
只在**大场景瓦片**上生效。把两者合起来看，指向一个尚未被利用的结构性缺口：

本方法要把真值网格按面法向分类（`src/_t_ecd_class.py`），发现
**真值面积约 89% 属于近竖直面（|n_z| < 0.3）**。而"沿 z 轴投影的高程面"
（§7.4 的 DSM 以及后续所有 z 向加密层）在几何上只能描述**水平面**——
在墙体的中段（既非檐口也非地面），沿 z 的高程面对应"该 (x,y) 处无采样"，
因此这些区域在当前所有候选版本中**始终是空集**。

### 7.10.2 算子定义：x / y 双轴 min∪max 高程面

对每个样本，仅使用**该样本自己的输入点云**与**本方法上一版网格**（不读真值、不用外部数据）：

1. **尺度门控**：计算点云包围盒对角线 `diag`；`diag < 30 m` 的样本原样输出。
2. 对命中样本，沿 **x 轴**与 **y 轴**分别做轴置换投影（如 `(x,y,z) → (y,z,x)`），
   在 **g = 2.0 m** 规则格网上取每格的**最低高程（min）与最高高程（max）**，
   各自三角化（`max_edge` 缺省 = 3g = 6 m），得到 4 个几何块：
   x-min、x-max、y-min、y-max。
3. **写入方式**：原网格 OBJ 文本**原封不动**，新块以 `v`/`f` 行**纯文本追加**在文件末尾
   （顶点序号整体偏移）⇒ 输出是上一版结果的**字节前缀超集**，
   在构造上不可能破坏已有几何，也使"叠加"天然可回退。

对应代码 `src/_t_mads_apply.py`（MADS = Multi-Axis DSM）。

### 7.10.3 构建结果（4000 栋）

```bash
python src/_t_mads_apply.py --meshd data/work/final_v29 --plyd data/work/ply \
    --outd data/work/final_v37 --axes x,y --g 2.0 --diag-min 30 \
    --face-cap 200000 --cell-cap 400000 --jobs 6
```

- 有效 4000，**门控命中 1878（47.0%）**，错误 0；命中样本 `diag` 中位 **54.5 m**。
- 新增面数 **中位 555 / 均值 1932 / 合计 3,628,488**；输出目录 283.4 MB。
- 无真值自检（`verify_submission.py`）：覆盖率 4000/4000、可解析 4000、退化 0、
  尺度比 p50 1.003 / max 1.196，全部通过。

### 7.10.4 线上结果与受控对照

v37 在公开榜取得 **FINAL 3.83416 / CD 2.96191 / ECD 5.14252**，
相对 v29 的 **ΔFINAL −0.17425**，且 **ΔCD −0.19675 与 ΔECD −0.14053 同向双降**——
这与 §7.4 之前那些"单通道博弈"型改进有本质区别。

同批次、同预算的 z 轴加密对照（v35 = 1.5 m、v36 = 1.0 m）分别只取得
**−0.01479** 与 **−0.09060**，即**多轴补墙约为单轴 1.0 m 加密的 1.9 倍**。
尤须指出 v35 的 **ECD 反而变差 +0.10163**：单轴加密的收益与真值边网尺度存在
**非单调耦合**，"更细"并不等价于"更好"，必须按**轴（方向）**而非仅按分辨率做决策。

### 7.10.5 边界与诚实声明

- 本算子是**对所有命中样本无差别叠加**，不含任何样本级筛选或门控阈值调参；
  因此它**不是**针对指标的定向拟合，而是对"几何缺失方向"的结构性补齐。
- 在墙体不占主导的样本（如大面积平屋顶厂房）上，该方向无点，算子不产生几何，
  属安全行为；同时也意味着**该类样本没有获益**。
- 大场景瓦片上的"贴点云包围盒空壳"问题（§8.3.2）依然存在，MADS 不解决该问题。

- 从第 2 次到第 19 次（`b23c319f` → `2239bdf5`），FINAL 由 **5.16638 降到 3.83416（−25.8%）**，

  分阶段看：v8 → v21（重建修正 + ECD 定向算子）贡献 −18.2%，
  v21 → v37（DSM 逐层加密 + 多轴补墙）再贡献 **−9.3%**。
- v9r（`b19826fd`）只改了 **48 栋（1.2%）**，却带来 FINAL −0.86% ——
  折算约 **每改动 1 栋 ≈ 3.4 点 FINAL**，印证了"尾部集中"的判断。
  v9r 的改动量极小（1.2%）而收益显著，
  说明**在正确的位置做小改动**比全量重跑更有效。
- **第 13 次是本方法唯一一次"ECD 改善远超 CD"的提交**：
  ΔECD −0.328 vs ΔCD −0.079，比值 **4.2 : 1**。

- **第 14 次（v22）是一次单变量消融**，代价为 1 次额度，产出是一条硬约束

### 8.3 局限性（如实陈述）

1. **尾部仍未攻克。** 本方法已定位但未能解决最差约 400 栋：
   其无真值特征为"整栋偏离点云"（`p2m ≥ 0.5`），网格常呈
   "从一个顶点放射出的扇形三角形"或"巨型板"。所有已测试算子针对它们均净负。
   由于 realbench 的尾部被截断（§4.5），本方法不具备验证该问题的手段。
2. **场景瓦片未被真正处理。** 输入是多建筑场景瓦片（如 2377 含 933k 点、
   跨 626 × 510 m），而 City3D 按"单栋含地面"的方式被调用。
   本方法只做到了"不制造灾难"（场景足迹跳过），未做到"正确分栋重建"。
   这一点在 v21 之后被部分补偿：门控 DSM 恰好只在场景瓦片上生效（§7.4），
   相当于用一张地表 DSM **兜住了**本应由分栋重建提供的地面/地表几何，
   但它是"叠加"而非"替代"，§8.3.2 的问题仍然存在。
3. **ECD 的绝对水平仍落后于头部队伍。** walls、门控 DSM 与多轴补墙已把 ECD 降 **21.1%**
   （6.51847 → 5.14252），但 5.14252 仍高于榜首 hhy6（4.3037）、Louis77777（4.929）
   与 Chuniby0（5.0106），仅优于 yyyu-1010（5.157）。
   （此处引用 `docs/official/赛道三_官方_leaderboard_public.md` 的 2026-10-03 快照；
   榜单持续变动，仅作同期参照。）
   机理上这是**结构性的**：\(\S7.2\) 已证明真值在大场景下是一张
   边密度 ≈ 8 m 边/m² 的高密度三角化曲面，而本方法的 LoD2 输出边数少两个数量级，
   ECD 的 `E2` 项（真值→预测）存在**难以消除的覆盖缺口**。
   本方法尚未找到在不抬高 `E1` 的前提下进一步补齐该缺口的手段。
4. **realbench 样本量偏小（32 栋有真值可用）**，
   分组结论（如 0.15–0.3 档 +3.33%）样本数只有 5 栋，存在统计噪声，
   本方法没有据此设计任何门控开关。

## 11. 结论

本方法的贡献可以归纳为五点：

1. **一个可执行的评测校准流程。** 逐行复现官方评测脚本、确认坐标系与单位、
   把 CD 拆成 CD1/CD2，从而建立起"线上分数可以离线预测、离线改动可以事前验证"的
   双向通道。
2. **一套无真值条件下的统计决策方法。** 以 `p2m_p90` 为核心的代理指标、
   双锚点校准的 FINAL 预测器、尾部集中度分解，
   把一个"没有 GT 的 4000 栋重建问题"变成了可量化、可排序、可验证的工程问题。
3. **一个在真值上被验证净增益的几何算子。** 「只补足迹侧壁、不加顶底」的 walls 算子，
   在公开真实基准上取得 `ΔFINAL = −4.83%`（27/32 改善），且 CD 与 ECD 同时改善；
   它同时具备物理可解释性（墙面落在真实墙面上）与无真值可验证性
   （`p2m` 零退化），是本方法能够在不触碰任何标签信息的前提下稳定推进分数的支点。
4. **一条"沿信息缺口方向"的算子设计原则，以及它的受控验证。**
   本方法先把 z 轴 DSM 加密推进到收益递减（v29 → v36 仅 −0.091、v35 仅 −0.015），
   随后识别出**真值约 89% 面积为竖直墙面、而 z 向高程面在墙中段恒为空集**这一结构性缺口，
   改沿 **x / y 双轴**做 min∪max 高程面（MADS），一次性取得 **ΔFINAL −0.17425**
   （约为同期单轴加密的 **1.9 倍**），并把最终成绩定格于 **3.83416**。
   这一对照说明：**在同一个方向继续加密的边际收益，远低于切换到信息真正缺失的方向**。
5. **一次受控的同批次对照，得到一条负结果。** z 轴 1.5 m 档（v35）出现 ECD 反噬
   （ΔECD **+0.10163**），而 1.0 m 档（v36）正常（ΔECD −0.07145），
   说明单轴加密与真值边网尺度之间存在**非单调耦合**——"更细"并不等于"更好"。

同时本方法如实报告了**未解决的问题**：多建筑场景瓦片的正确分栋与重建，
以及最差约 400 栋（占 FINAL 36%）的翻盘，均超出当前方案能力范围。
