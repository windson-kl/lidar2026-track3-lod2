# 面向机载 LiDAR 场景瓦片的 LoD2 建筑重建

**技术说明文档**

队伍：wind　｜　参赛赛道：赛道三（LoD2 建筑物三维重建）　｜　评估平台用户名：wind-kl

---

## 摘要

本文面向第十届全国激光雷达大会数据处理大赛赛道三，处理对象是 4000 幅机载 LiDAR 点云场景瓦片。与常见的单栋建筑重建任务不同，这些瓦片平均覆盖多栋建筑及地面、植被，最大一幅的包围盒对角线达 1040 m、点数 93 万。评测在原始坐标系下以米为单位进行，指标由 Chamfer 距离（CD）与边缘一致性距离（ECD）按 0.6:0.4 加权构成，得分越低越好。

本文的方法由三部分构成。第一部分是主干重建，采用开源方法 City3D 的屋顶平面整数规划，并针对场景瓦片修改其候选面数量上限；对规划失败或退化的样本，用纯几何的栅格化-简化-拉伸流程兜底，保证 4000 幅瓦片全部有可解析输出。第二部分是四个只作用于几何或拓扑的后处理算子：立面补全、门控 DSM 叠加、多轴高程面补强、大场景格网自适应与折边切开。这四个算子都只使用样本自身的点云与自身已有的网格，不读取任何真值，输出为对原 OBJ 文本的追加或顶点重排，因此不会破坏已有几何。第三部分是在无法获得测试集真值的前提下建立的验证体系，包括官方指标的本地逐位复现、代理指标的显著性筛选、双锚点线性预测器与线上-离线传递率的标定。

最终提交在官方评测上取得 FINAL 3.56886（CD 2.59888、ECD 5.02382），官方基线为 9.8437。在 60 栋具备真值的公开配对样本上，完整流程相对不含本文四个算子的基础流程将 FINAL 由 3.0359 降至 2.7688（−8.80%），CD 由 2.7775 降至 2.4890（−10.39%），ECD 由 3.4236 降至 3.1885（−6.87%），两项主指标同向下降。

## 1. 任务、数据与约束

### 1.1 数据

| 数据 | 规模 | 用途 |
|---|---|---|
| 测试点云 | 4000 幅 `.xyz`，米制，已居中于原点 | 最终提交对象 |
| 公开配对样本 | 23000 组（点云 + 参考网格） | 算子开发与消融 |
| 公开基准子集 | 60 栋 + 40 栋（含参考网格） | 本地评测与真值验证 |

测试瓦片不是单栋建筑。以样本 `2377` 为例：933,386 点，包围盒 626×510×655 m，对角线 1040 m，内含多栋建筑、成片地面与植被。全集中位对角线为 28.8 m，p90 为 104.4 m，最长 1039.8 m。这意味着同一个流程必须同时处理两类输入：一类是单栋或少数几栋构成的紧凑瓦片，另一类是整街区尺度的大瓦片。二者的最优参数并不相同，这是本文后续多个设计选择的直接来源。

### 1.2 三个约束

**约束一：测试集没有真值。** 公开集与测试集的样本 ID 空间不同，无法用 ID 对齐。任何"在本地看到指标变好"的结论，都不能直接外推到线上。

**约束二：评测在原始坐标尺度下进行。** 官方评测脚本中，去除质心与按尺度归一化的两行代码被注释掉了。这一点在开发早期被忽略，导致一次提交的 CD 达到 49.30——该数值恰好等于点云包围盒对角线均值（约 24 m）的两倍，说明评测端把提交网格视作"比点云小 24 倍"的模型。确认口径后，同样几何的 CD 回到 4.27 量级。本文所有后续实验均在原始坐标、米制下完成。

**约束三：LoD2 的结构假设与真值形态存在系统性差距。** 参考网格的平均面数为 871，而典型 LoD2 输出平均面数约 101。参考网格是一张高密度三角化曲面，其锐边网络几乎铺满整个表面；ECD 的定义使一张"处处有边"的网格天然占优。这决定了不能只追求平面拟合精度，还必须在正确位置增加边。

### 1.3 评测指标

设提交网格为 M、参考网格为 G，官方口径下：

```
CD  = CD1 + CD2        （M→G 与 G→M 两个方向的 Chamfer 距离之和）
ECD = E1  + E2         （两方向的边缘一致性距离）
FINAL = 0.6 × CD + 0.4 × ECD
```

另有 NC、V_Ratio、F_Ratio 三项辅助输出，不计入最终分。本文在本地复现了该口径，复现结果与官方在公开集的公开分数逐样本一致，这是后续所有离线实验可信的前提。

## 2. 方法总体框架

### 2.1 流程

```
4000 幅 .xyz
 ├─[1] 预处理          .xyz → .ply，同时输出几何体检（点数、包围盒、对角线、缺失率）
 ├─[2] 主干重建        City3D 屋顶平面整数规划（候选面上限 600 → 5000）
 ├─[3] 兜底重建        栅格化 → RDP 简化 → 拉伸，覆盖主干的失败样本
 ├─[4] 后处理          离群面剔除、外法向统一、主轴正交化、共面片合并
 ├─[5] 质检补救        结构判据扫描，命中样本用备选参数重跑并择优
 ├─[6] 立面补全        沿足迹边界补侧壁
 ├─[7] 门控 DSM 叠加    点云格网抽样 + Delaunay，按尺度门控追加
 ├─[8] 多轴高程面      沿 x / y 轴各取 min∪max 高程面追加
 ├─[9] 大场景自适应     按对角线切换格网间距
 └─[10] 折边切开 + 打包  30° 折边处切分网格，输出平铺 zip
```

第 3 步存在的意义是覆盖率。比赛要求提交 4000 个 `.obj`，任何一个缺失都直接体现为该项 CD 极大。主干在场景瓦片上存在确定性的失败模式（第 3.2 节），因此兜底不是可选项。

### 2.2 坐标与单位

所有算子在同一坐标系下工作：点云已居中，单位为米，z 轴向上。输出网格保持输入点云的坐标框架，不做任何归一化、缩放或重新居中。这是约束二直接决定的——任何归一化都会使 CD 放大到不可用。

## 3. 主干重建

### 3.1 City3D 的适配

City3D 通过从点云中提取候选平面，再用整数规划在候选面中选出一组构成闭合多面体。其命令行接口中有一个参数 `max_allowed_candidate_faces`，默认值 600。

该参数在单栋建筑上几乎不会被触发，但在场景瓦片上会成为主导因素：多栋建筑的候选面累加后轻易超过 600 个，超出后规划器退化到一条"剔除竖直方向约束"的妥协路径，输出倾向于贴地铺面而不是立起墙体。把它提高到 5000 后，这一退化基本消失。

需要强调，这个参数是分支开关，不是单调阈值。低于某值时走妥协路径，高于某值时走完整规划路径，中间没有渐变。因此不存在"调到某个折中值"的做法，只能取足以覆盖候选面数量的上限。

### 3.2 三类失效与兜底

在 4000 幅瓦片上，主干输出存在三类可识别的失效：

1. **完全失败**：规划无可行解，无输出文件。
2. **退化输出**：有输出但面数极少，通常是一张贴地平面或空壳。
3. **尺度错误**：输出存在，但包围盒与点云包围盒的对角线之比超出合理区间，表现为爆炸（比 > 1.5）或塌陷（比 < 0.6）。

第 3 类的判据用比值而非绝对值：

```
ratio = 网格包围盒对角线 / 点云包围盒对角线
健康区间 [0.85, 1.20]
```

这一比值只依赖样本自身，不需要真值，因此可以用于线上全集的自检。它对"爆炸网格"和"兜底塌陷"都敏感，是本文在无真值条件下最有效的结构体检指标。

对上述三类，兜底流程用纯几何方式重建：把点云投影到栅格，逐格取最低高程得到地面，对建筑区域取最高高程得到屋顶，用 RDP 简化轮廓，再拉伸成立面。兜底结果在精度上明显弱于成功的主干输出，但保证有可解析几何，避免 CD 出现量级跳变。

### 3.3 质检补救

质检阶段扫描三类结构问题并定向补救：

- 兜底产物与主干产物在文件名后缀上不可区分。早期版本中，目录里 89.4% 的文件实际是兜底品，而流程无法识别。修复方式是让兜底产物携带独立标识，使后续所有统计与筛选能区分来源。
- 爆炸/塌陷网格没有拦截（判据即第 3.2 节的 ratio）。
- 失败原因不落盘，导致同一配置被反复重试。

补救策略是对命中样本换一组备选参数重跑，并在两版结果中按 ratio 与面数择优。这一步不改算法，只提高有效产出的比例。

## 4. 后处理算子

四个算子的共同前提：只使用该样本自身的点云与自身已有的网格，不读取真值；输出为对原 OBJ 文本的追加，原顶点与面片顺序、数值完全不变。这样即使算子失效，也不会破坏已有几何，最坏情况退化为原输出。

### 4.1 立面补全

**动机。** LoD2 输出常只有屋顶面，立面缺失或只覆盖上半段。CD 中的 M→G 方向因此出现系统性偏差，而 G→M 方向正常。表现为 CD1 偏大而 CD2 偏小。

**算子。** 取网格的足迹外轮廓（顶点按位置焊接后取边界边），对每条边界边沿竖直方向拉出一个四边形。竖直范围由该足迹内点云的高程分位确定：

```
z0 = 足迹内点云 z 的 p2 分位
z1 = min(足迹内点云 z 的 p30 分位, z0 + 150 m)
若 z1 - z0 < 0.5 m 则跳过该足迹
```

只加侧壁，不加顶面，不加底面。这不是简化，而是必要的：完整棱柱（侧壁 + 平顶）在真值上一致为负。原因是平顶会在建筑上方凭空产生一片水平面，它离参考曲面更远，且会额外引入一圈水平边；伤害主要来自顶面。

**场景保护。** 足迹 XY 对角线大于 150 m 时跳过，视为场景外轮廓而非单栋建筑，避免在大瓦片外沿造出一圈巨型墙。全集 4000 幅中有 126 幅（3.1%）命中该保护。

**验证。** 在 32 栋具有参考网格的紧凑样本上，相对不含该算子的同流程：FINAL −3.65%（−0.0560），CD −0.0944，ECD +0.0016，25 栋改善、6 栋变差。CD1 与 CD2 同时改善（0.744→0.703 / 0.491→0.463），说明补上的侧壁几乎不引入新误差，只是覆盖了原本缺失的面。

### 4.2 门控 DSM 叠加

**动机。** 在大瓦片上，参考网格是密集三角化曲面，边网铺满表面；而 LoD2 输出面数只有百级，绝大多数表面区域没有任何边。ECD 因此成为瓶颈。

**算子。** 把该样本的点云投影到规则格网，每格取最低高程（min），对得到的规则高程图做 Delaunay 三角化，删除长度超过 3 倍格网间距的边（3 m 格网时为 9 m），把剩余三角形以纯文本追加到 OBJ 末尾。格网间距取 3 m。

删长边的目的不是简化，而是保留"承重结构"：如果没有边上限，Delaunay 会在点云空洞处连出跨越数十米的长三角形，这些三角形的边既不对应任何真实结构，又会把 ECD 的其他边稀释掉。实测去掉该上限后，线上 ECD 反而上升。

**门控。** 增益与场景尺度强相关。点云对角线 `ply_diag` 与 FINAL 变化量的相关系数为 −0.826（Spearman −0.749）：小场景增益接近零，大场景增益很大。因此在 `ply_diag > 40 m` 时才启用，避免在紧凑样本上引入无效面片。

**验证。** 在 20 个高复杂度样本上，与不加 DSM 的网格相比：

| 配置 | CD | ECD | FINAL |
|---|---|---|---|
| 不加 DSM | 18.75 | 33.78 | 24.76 |
| 2 m 格网 | 17.52 | 28.42 | 21.88 |
| 5 m 格网 | 17.11 | 25.27 | 20.37 |
| 10 m 格网 | 17.13 | 22.28 | 19.19 |

三个格网间距下 CD 与 ECD 同时下降，其中 ECD 的降幅（16%–34%）明显大于 CD（7%–9%），与该算子的动机一致。

### 4.3 多轴高程面

**动机。** 4.2 节的高程面沿 z 轴投影，只能覆盖水平面。参考网格中约 89% 的面积是近竖直面，而这些面在沿 z 投影的高程图中没有任何几何。墙体的中段因此始终是空的。

**算子。** 除 z 轴外，再沿 x 轴与 y 轴各生成一对高程面：把点云按轴置换投影到 (y,z) 或 (x,z) 平面，在规则格网上取每格的最低与最高高程，分别三角化。四块几何（x-min、x-max、y-min、y-max）以纯文本追加。

参数：基础格网 1.5 m，单样本新增面数上限 40000，格元上限 100000。不设尺度门控（下限置 0），4000 幅全部参与。

**与大场景自适应的耦合。** 1.5 m 格网在大瓦片上会产生过多面片。对 `ply_diag > 80 m` 的样本，格网间距切换为 3 m。全集有 606 幅命中该切换。这是同一算子的两个密度档，不是两个算子。

**验证。** 在 16 个随机场景上，均值（n=16）：

| 配置 | CD1 | CD2 | E1 | E2 | FINAL |
|---|---|---|---|---|---|
| 不加高程面 | 4.2277 | 1.5524 | 7.7164 | 2.3022 | 7.4755 |
| 仅 z 轴 | 3.8570 | 1.4579 | 7.4746 | 1.9927 | 6.9758 |
| 仅 x 轴 | 4.0838 | 1.5193 | 7.5773 | 2.0644 | 7.2185 |
| 仅 y 轴 | 4.0430 | 1.5130 | 7.5729 | 2.0442 | 7.1804 |
| x+y（1.5 m） | 3.6322 | 1.4341 | 7.2823 | 1.8940 | **6.7103** |
| x+y（1.0 m） | 3.7014 | 1.4334 | 7.3601 | 1.8896 | 6.7808 |

单轴补强的增益约为 −0.26 至 −0.50，双轴合并后为 −0.765，接近两者之和，说明 x/y 两个方向覆盖的是不同朝向的墙面，增益基本可加。继续加密到 1.0 m 反而略差，说明该方向已饱和，误差来源转移到别处。

### 4.4 折边切开

**动机。** 折边两侧属于不同平面。若一个三角面横跨折边，它的边既不属于任何一个平面，也不与参考网格的边网重合。这类边对 ECD 是纯噪声。

**算子。** 检测相邻面法向夹角超过 30° 的边（与官方锐边判据取同一阈值），沿该边把网格切分，使折边成为显式补丁边界。切开只改变拓扑连接与顶点复制，不移动任何顶点，因此 CD 逐位不变。

**效果。** 这是唯一一个 CD 逐位不变而 ECD 下降的操作。在 4000 幅上，切开后的顶点数中位由 484 增至 723（×1.47），补丁数中位 91。有 15 幅未能切开（几何不满足切分条件），保留切分前版本。

## 5. 无真值条件下的验证体系

### 5.1 官方指标的本地复现

第一步不是改算法，而是确认尺子。做法是逐行复现官方评测脚本，在 40 栋与 60 栋两组公开配对样本上比对本地结果与官方公开分数，确认逐样本一致。这一步暴露了归一化被注释的问题，也确立了后续所有实验的坐标系。

### 5.2 代理指标的筛选

在无法直接测 FINAL 时，需要一个可离线计算的代理量。候选包括各类点面距离分位数与平均量。评估标准是代理量与真值侧 ECD 及 FINAL 的相关系数：

| 代理量 | 与 ECD 相关 | 与 FINAL 相关 |
|---|---|---|
| p2m_p90（点到面距离 p90） | +0.913 | +0.894 |
| 均值口径 | +0.858 | — |

取 p2m_p90。它与 ECD 的相关性显著高于均值，原因是 ECD 对局部偏差敏感，而均值会被大量已经很好的区域稀释。

### 5.3 双锚点预测器

用三个特征拟合线性的 FINAL 预测器，再用两个独立的线上实测点确定截距与斜率，使离线指标可以换算为线上预期。该预测器在留出样本上的决定系数 R = 0.924；用一次提交前的预测值与实际出分比对，预测 4.678、实际 4.67808。

### 5.4 传递率的标定

离线变化量与线上变化量不是同比例。在多个受控改动上测得：CD 的离线-线上传递率约 8.7%，ECD 约 22.9%。由于 FINAL 中 ECD 的权重为 0.4、CD 为 0.6，换算后线上 ECD 对总分的话语权约为 CD 的 2.6 倍。

这条结论直接改变了后续的优化方向：同样的离线 CD 改进，其线上价值只有 ECD 改进的三分之一强。它也是 4.2 与 4.3 两节把重心放在边缘一致性的依据。

同时观测到传递率不是常数：同一次离线 ΔECD，线上可以表现为 −0.328，也可以反号至 +0.111。因此本文把"改动必须保持边的局部性"设为提交前硬约束——任何一处改动如果引入了与原结构无关的长边或大面，即使离线指标下降也不提交。

## 6. 实验

### 6.1 设置

本地评测分两组：

- **60 栋紧凑样本**：具有参考网格，几何规模与单栋建筑相当，用于测量流程整体的指标变化。
- **20 个高复杂度样本**：用于测量对边缘敏感的算子。

官方成绩来自评测平台的公开分数。所有本地数字均在原始坐标、米制下按官方口径计算。

### 6.2 整体效果

在 60 栋样本上，将不含本文四个算子的基础流程与完整流程对比。两次运行使用同一批输入、同一主干参数、同一参考网格，仅差四个后处理算子：

| 配置 | CD | ECD | FINAL |
|---|---|---|---|
| 基础流程（主干 + 兜底 + 后处理 + 质检） | 2.7775 | 3.4236 | 3.0359 |
| 完整流程（加四个算子） | 2.4890 | 3.1885 | **2.7688** |
| 变化 | −10.39% | −6.87% | **−8.80%** |

完整流程在该集合上的分布：FINAL 中位数 0.9763，p10 0.4448，p90 5.8845，最大 32.46。分布长尾明显——多数样本已经很好，少数样本占据总分的主要部分。

最终提交在官方评测上取得 FINAL 3.56886（CD 2.59888、ECD 5.02382），提交编号 633ad951，提交时间 2026-10-08 14:38:54。官方基线为 9.8437。

### 6.3 算子消融

4.1 至 4.3 节分别给出了单个算子在受控集合上的效果。汇总如下（各自在对应集合上测量，不可横向相加）：

| 算子 | 集合 | 主要指标变化 |
|---|---|---|
| 立面补全 | 32 栋紧凑样本 | FINAL −3.65%，CD −0.0944，ECD +0.0016 |
| 门控 DSM | 20 个复杂样本 | CD −8.7%，ECD −25.2%（5 m 格网） |
| 多轴高程面 | 16 个随机场景 | FINAL −10.2%（x+y 相对无高程面） |
| 折边切开 | 4000 幅全集 | CD 逐位不变，顶点数 ×1.47 |

四个算子的作用点不同：立面补全补的是缺失的面，DSM 与多轴高程面补的是缺失的边，折边切开清理的是错误的边。三者在 60 栋集合上的合并效果为 −8.80%，低于各自单独效果之和，说明覆盖区域存在重叠——已经补上立面的区域，其边缘也同样被后续算子的边网覆盖。

### 6.4 参数敏感性

| 参数 | 取值 | 依据 |
|---|---|---|
| 候选面上限 | 5000 | 600 时大瓦片退化到妥协路径 |
| 立面 z0 / z1 | p2 / p30 | p25 及以上时墙过高，p20 及以下覆盖不足 |
| DSM 格网 | 3 m | ECD 与面数的折中；格网更密时 ECD 改善但面数膨胀 |
| DSM 边上限 | 9 m（3g） | 去掉后线上 ECD 上升 |
| 高程面格网 | 1.5 m | 1.0 m 无进一步收益 |
| 大场景切换阈值 | 80 m | 超过该尺度 1.5 m 格网面数失控 |
| 折边阈值 | 30° | 与官方锐边判据同阈值 |

### 6.5 失败案例

**多建筑瓦片未被真正分栋。** 本文流程把整幅瓦片当作一个场景处理，用一张 DSM 覆盖地表，没有做建筑实例分割。对瓦片中的每一栋建筑，重建精度依赖于主干能否在场景尺度上正确分离候选面。当建筑间距小、屋顶高程接近时，主干倾向于把它们合并为一个多面体。这是当前最大的结构性短板，也是长尾中高 FINAL 样本的主要来源。

**尾部约 400 栋未攻克。** 在 60 栋集合上，最差 10% 样本的 FINAL 占全集合总和的 36.0%。针对这批样本尝试过的算子（加密、平滑、删面、保留主连通分量）在真值上全部为负，说明问题不在参数而在方法结构。

**38 幅点云过稀无法生成 DSM。** 最典型的样本仅 139 点、对角线 4.96 m，格网化后没有有效格元，算子自动跳过，保留原网格。

## 7. 与已有方法的差异

本文主干采用公开方法 City3D，因此差异集中在两处：对主干的适配，以及主干之外的四类补充。

**适配层面。** City3D 面向单栋建筑的点云设计，其候选面数量上限的默认值在场景瓦片上会成为主导约束。本文识别出该参数是分支开关而非连续阈值，并据此重设。这一改动不涉及算法本身，但决定了主干在场景瓦片上是否走完整规划路径。

**补充层面。** 已有的 LoD2 重建工作普遍以平面拟合精度为目标，输出稀疏网格；本文在三个方向上补足：

1. **补缺失的面。** 立面补全针对"只有屋顶、没有立面"这一常见失效，且明确只补侧壁——含平顶的完整棱柱在所有测试中均为负，这一点与"输出闭合实体"的常规做法相反。
2. **补缺失的边。** 参考网格的边密度比典型 LoD2 输出高一个量级以上。本文用两张不同投影方向的高程图（z 轴 DSM、x/y 轴 min∪max）提高表面边密度，并按尺度门控，避免在小样本上引入无效几何。
3. **清理错误的边。** 折边切开使折边成为显式边界，减少跨折边三角面对 ECD 的噪声贡献。

**验证层面。** 由于测试集无真值，本文把相当一部分工作放在"如何在不看真值的情况下判断改动是否有效"上：本地逐位复现官方指标、用相关性筛选代理指标、用双锚点预测器把离线量换算为线上预期、标定 CD 与 ECD 的传递率差异。其中传递率差异（ECD 的线上话语权约为 CD 的 2.6 倍）直接决定了后续优化的权重分配。

需要说明的是，上述补充不改变主干的方法性质。本文没有提出新的平面提取或整数规划算法，贡献在于识别人工流程在场景瓦片上的具体失效点，并给出可验证、可回退的补救。

## 8. 局限

1. 未做建筑实例分割，多建筑瓦片按整体处理，建筑密集处易合并。
2. 尾部样本未攻克。在 60 栋集合上最差 10% 占 FINAL 总和的 36.0%，现有算子对其均为负增益。
3. ECD 与领先方案仍有差距。参考网格的边密度约为 8 m 边/m²，比本文输出高两个数量级，单纯提高边密度会同时抬高 CD，存在明确的上界。
4. 兜底流程的几何精度明显低于主干成功输出，其存在目的是覆盖率而非精度。
5. 线上-离线传递率在不同改动上不稳定（同一离线 ΔECD 可对应 −0.328 至 +0.111），因此只能作为方向性参考，不能作为定量预测。

## 9. 可复现性

**代码。** 完整流程以 CC BY 4.0 许可证公开发布：https://github.com/windson-kl/lidar2026-track3-lod2。包含预处理、主干封装、兜底、后处理、质检、四个算子、打包与校验脚本。

**环境。** Python 3.9，numpy 2.0.2，trimesh 4.9.0，scipy；主干为 C++ 编译的 City3D 命令行程序。

**代码结构。** 仓库按流程阶段组织，各阶段脚本可独立运行，中间产物落在 `data/work/` 下按阶段命名的目录中：

| 文件 | 阶段 | 作用 |
|---|---|---|
| `src/prepare.py` | 预处理 | `.xyz` 转 `.ply`，输出几何体检 |
| `src/run_batch.py` | 主干 | 串联重建、兜底、后处理、质检四个阶段 |
| `src/fallback.py` / `src/postproc.py` / `src/qc_repair.py` | 主干 | 由 `run_batch.py` 调用，非独立命令行 |
| `src/metrics.py` | 评测 | CD / ECD / NC / V_Ratio / F_Ratio 的本地实现 |
| `src/_t_build_walls.py` | 算子 | 立面补全 |
| `src/_t_apply_clean.py` | 算子 | 尾部清理（近中性，可不启用） |
| `src/_t_dsm_apply.py` | 算子 | 门控 DSM 叠加 |
| `src/_t_mads_apply.py` | 算子 | 多轴高程面，含大场景格网自适应 |
| `src/_t_creasesplit_apply.py` | 算子 | 折边切开 |
| `src/package.py` / `src/verify_submission.py` | 打包 | 生成 zip 与提交前校验 |
| `src/_t_ecd_risk.py` / `src/_t_check_ab.py` | 诊断 | 支撑第 5 章结论的对照实验工具 |

**复现步骤。**

```bash
# 1) 预处理：.xyz -> .ply，同时输出几何体检
python src/prepare.py --src data/raw/test_xyz/LiDAR_xyz --dst data/work/ply

# 2) 主干重建、兜底、后处理、质检（run_batch 串联第 3.1 至 3.3 节全部步骤）
#    候选面上限由默认 600 提高到 5000
python src/run_batch.py --stage all --src data/raw/test_xyz/LiDAR_xyz \
    --work data/work --jobs 8 --max-faces 5000
#    产出落在 data/work/final

# 3) 立面补全（只补侧壁）
python src/_t_build_walls.py --mode build --base data/work/final --out data/work/walls \
    --z0q 2 --z1q 30 --jobs 8

# 4) 尾部清理
python src/_t_apply_clean.py --src data/work/walls --dst data/work/clean \
    --ply data/work/ply --mode far_sliv --sliv 40 --jobs 8

# 5) 门控 DSM 叠加（3 m 格网，边上限 3g = 9 m，门控 40 m）
python src/_t_dsm_apply.py --meshd data/work/clean --plyd data/work/ply \
    --outd data/work/dsm --g 3.0 --diag-min 40 --jobs 5

# 6) 多轴高程面（含大场景格网自适应）
python src/_t_mads_apply.py --meshd data/work/dsm --plyd data/work/ply \
    --outd data/work/mads --axes x,y --g 1.5 --diag-min 0 \
    --g-big 3.0 --diag-split 80 --face-cap 40000 --cell-cap 100000 \
    --jobs 6 --report logs/apply_mads.json

# 7) 折边切开（30°，与官方锐边判据同阈值）
python src/_t_creasesplit_apply.py --meshd data/work/mads --outd data/work/cs \
    --crease 30 --jobs 6

# 8) 打包与校验
python src/package.py --src data/work/cs --out out/submission.zip
python src/verify_submission.py --zip out/submission.zip --ply data/work/ply --expect 4000
```

**可复现性说明。** 打包脚本在生成 zip 前会执行一次无真值自检，检查四项：条目数是否为 4000、全部条目是否可直接解析、几何是否非退化、包围盒比值是否落在 [0.85, 1.20]。最终提交包的实测结果为：4000 条目、嵌套目录 0、非 obj 条目 0、CRC 全部通过，比值中位 1.004、p95 1.031、最大 1.207（唯一一条略高于阈值，属尺度偏大，非量级错误）。

**随机性。** 流程中唯一的随机性来自点云抽样的固定种子（`seed=0`），在给定输入与参数下输出确定。
